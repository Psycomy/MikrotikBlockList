# v3 Fase 5 — IPv6 (opcional, desactivado por defecto) · Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** publicar listas IPv6 (*full* y *lite*) y dejar que un router con IPv6 las active al instalar (`:global mblIpv6 true`). Sin eso, el router no crea nada de IPv6.

**Arquitectura:**
- Los parsers dejan de descartar IPv6.
- El generador normaliza cada familia por separado y publica `routeros6-<variante>.txt` y `blocklist6[-lite].txt`. IPv6 es **de mejor esfuerzo**: si falla, no se publica IPv6 y no se bloquea IPv4.
- En el router, `mbl-update` procesa IPv4 y, si está activado, IPv6, con el mismo lector seguro. Cada familia tiene su propio par de listas, sus reglas en `/ipv6 firewall raw` y su copia de arranque. Un fallo en IPv6 nunca toca IPv4.

**Tecnología:** Python 3.12 con la biblioteca estándar, scripting de RouterOS v7 y el harness e2e.

**Spec:** `docs/superpowers/specs/2026-10-21-mbl-v3-hardening-design.md`, fase 5 y §7.8.

## Restricciones globales

### Generador

- **Fuente nueva `spamhaus-drop-v6`:**
  - formato nuevo `jsonl_cidr`: una línea JSON por red con clave `cidr`; las líneas sin `cidr` (metadatos) se ignoran;
  - `category = "attack"`, `variants = ["lite", "full"]`, **no** obligatoria;
  - `license_note` igual que la de Spamhaus DROP.
- **`ParseResult`:** `networks` puede contener redes IPv4 e IPv6. Las IPv6 dejan de ignorarse en todos los formatos, incluida la IP de `ip:port` entre corchetes en ThreatFox.
- **Normalización:** `normalize()` sigue siendo solo IPv4 y filtra por familia. Se añade `normalize6(networks, allowlist)`, que:
  - descarta lo no global, ULA `fc00::/7`, link-local `fe80::/10`, documentación `2001:db8::/32`, multicast `ff00::/8`, `::/8`, IPv4-mapped `::ffff:0:0/96`, NAT64 `64:ff9b::/96`, 6to4 `2002::/16` y Teredo `2001::/32`;
  - descarta todo lo más amplio que **/19**;
  - resta la allowlist IPv6, agrega y ordena.
- **Allowlist IPv6** en `allowlist.txt`, con un comentario encima de cada entrada:
  - Cloudflare: `2400:cb00::/32`, `2606:4700::/32`, `2803:f800::/32`, `2405:b500::/32`, `2405:8100::/32`, `2a06:98c0::/29`, `2c0f:f248::/32`;
  - GitHub (raw.githubusercontent.com): `2606:50c0::/32`;
  - DNS: `2001:4860:4860::8888`, `2001:4860:4860::8844`, `2620:fe::fe`, `2620:fe::9`.

  `load_allowlist` acepta IPv6.
- **Ficheros IPv6:**

  | Variante | Para el router | Para otros firewalls |
  |---|---|---|
  | full | `routeros6-full.txt` | `blocklist6.txt` |
  | lite | `routeros6-lite.txt` | `blocklist6-lite.txt` |

  La cabecera es la misma de la v3 con `family=ipv6`. Las direcciones `/128` se escriben sin máscara.
- **Límites IPv6:**
  - *full*: mínimo 50 y máximo 20.000;
  - *lite*: mínimo 20 y máximo 5.000;
  - caída del 50 % y crecimiento de 2x, con la regla de "caída explicada" de la fase 4.
- **Mejor esfuerzo:** si una variante IPv6 no pasa las comprobaciones, **no se publica ningún fichero IPv6**. Se avisa por stderr y en el *step summary*, y la salida es 0 si IPv4 está bien. IPv6 **nunca** provoca un código 1.
- **`stats.json`:**
  - se añade `"ipv6": {"published": bool, "variants": {"full": {"total": N}, "lite": {"total": M}}}`;
  - el resto no cambia;
  - el total previo IPv6 se lee de `ipv6.variants.<v>.total`; si no existe, no hay comprobación de caída ni de crecimiento.

### Router

- **Activación:**
  - global `:global mblIpv6`, con valores válidos `true`/`false` (booleano o cadena `"true"`/`"false"`); cualquier otro hace `:error` antes de cambiar nada;
  - si está vacía, se conserva lo instalado, leído de `:local ipv6 "yes"`/`"no"` en el `mbl-update` existente;
  - si no hay nada, vale `false`;
  - se incrusta con el marcador `@MBL_IPV6@`.
- **Objetos IPv6** (solo si está activado):
  - listas `/ipv6 firewall address-list` `mbl6-a`, `mbl6-b` y `mbl6-allow`; las sesiones de administración con dirección IPv6 entran en `mbl6-allow` como `MBL: admin`;
  - reglas en `/ipv6 firewall raw`, equivalentes a las 6 de IPv4 y con los mismos comentarios `MBL: …`;
  - fichero de arranque `mbl6-last.txt` (con `flash/` si existe) y descarga en `mbl6-new.txt`.
- **Desactivado:** el instalador borra cualquier objeto IPv6 de MBL de una instalación anterior (reglas `/ipv6 firewall raw` con comentario `^MBL:`, listas `mbl6-*` y ficheros `mbl6-*`). La desinstalación borra los de las dos familias.
- **`mbl-update`:**
  - tras la actualización IPv4 (que no cambia), si IPv6 está activado procesa `routeros6-<variante>.txt` con el mismo lector;
  - la validación de línea usa `:toip6` y un prefijo entre 19 y 128;
  - la cabecera exige `family=ipv6` y la variante instalada;
  - tamaño mínimo de fichero: 200 bytes; mínimo de entradas: *full* 50 y *lite* 20;
  - un fallo en IPv6 (descarga, validación o error inesperado) **nunca** modifica listas, reglas ni ficheros IPv4, ni el resultado de la carga IPv4, y deja el log `MBL: ipv6 …`;
  - el lock es el mismo y se libera siempre.
- **Mensajes de log IPv6:** `MBL: loaded <n> ipv6 entries into <list> (list generated <stamp>)` y `MBL: <fname> rejected (<motivo>), active ipv6 list kept`.
- **Mensaje final:** `MBL: installed (script <v>, variant <var>, ipv6 <yes|no>)`.
- **Versión:** `3.3.0`.
- **Nada leído del fichero se ejecuta.**
